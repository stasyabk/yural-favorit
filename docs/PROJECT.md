# YURAL FAVORIT — требования к MVP

**Версия:** 1.0  
**Статус:** согласованные требования к локальному тестовому проекту

## 1. Назначение

YURAL FAVORIT — тестовый веб-сайт для поиска автомобильных запчастей по артикулу. Данные о товарах, производителях, складских предложениях и аналогах приходят из действующего API Favorit Parts («Проценка»). Публичное размещение, продажи и личные кабинеты на этом этапе не планируются.

## 2. Стек и ограничения

- React на JavaScript (без TypeScript), сборка Vite.
- Redux Toolkit и RTK Query для запросов, кеша и состояний серверных данных.
- React Router для навигации.
- Bootstrap 5 и собственный CSS для оформления.
- `fetchBaseQuery` для HTTP-запросов; Axios и `createAsyncThunk` для стандартных API-запросов не нужны.
- **Без отдельного backend и proxy**: тестируем прямые запросы из браузера. Если политика CORS или другая браузерная блокировка мешает, останавливаем интеграцию и согласовываем решение, а не добавляем proxy самовольно.

## 3. Общий интерфейс

### Фиксированный Header

На всех страницах: слева логотип/надпись **YURAL FAVORIT**, справа разделы **Главная**, **О нас**, **Контакты**. На узких экранах — адаптивная навигация. Header не перекрывает контент.

### Главная (`/`)

- Крупная фоновая фотография **Ford Mustang** с затемнением в первом экране.
- По центру первого экрана — заголовок «Поиск автозапчастей», краткий подзаголовок, строка артикула и кнопка «Найти».
- После поиска **ниже поискового блока** показываются карточки найденных деталей/производителей.
- Каждая карточка содержит **только**: производитель, артикул, наименование, кнопку **«Цены и аналоги»**. Цена, остаток и склады на карточке не отображаются.
- Поиск запускается кнопкой и клавишей Enter; пустой ввод не отправляется.
- Состояния: до поиска, загрузка, успех, ничего не найдено, ошибка.
- При отсутствии результатов: «По вашему запросу ничего не найдено. Проверьте правильность артикула и попробуйте снова».
- Поисковая строка остаётся доступной для последующего поиска; история нескольких запросов не отображается и не хранится как отдельная функция.

### Цены и аналоги (`/parts/:brand/:number`)

- Над таблицами показываются выбранный производитель и артикул.
- Первая таблица: **предложения деталей выбранного производителя**.
- Ниже вторая таблица: **аналоги**.
- Одинаковые столбцы обеих таблиц: производитель, артикул, наименование, цена, остаток, склад, дата отгрузки.
- **Одна строка = предложение одной детали на одном складе**. Одна деталь может повторяться в нескольких строках.
- Сортировки и фильтров нет.
- При отсутствии аналогов или складских предложений показывается понятное пустое состояние, а не выдуманные строки.
- Есть кнопка **«Назад к результатам поиска»**.
- При возвращении в рамках текущей сессии приложения сохраняются введённый артикул и результаты поиска; повторный запрос при обычном возврате не должен выполняться. Для этого нужно предусмотреть соответствующее поведение кеша/состояния.
- URL страницы детали должен работать при прямом открытии; параметры `brand` и `number` кодируются надлежащим образом.

### Информационные страницы

- `/about` — «О нас», временное содержимое.
- `/contacts` — «Контакты», временное содержимое.

## 4. API

Источник: предоставленный пользователем PDF `wsprice.pdf` — документация Web-сервиса «Проценка» от 06.03.2023.

**Метод и URL:** `GET http://api.favorit-parts.ru/hs/hsprice/`.

### Поиск по артикулу

Параметры: `key` (клиентский ключ), `number` (артикул); без `brand` API возвращает товары разных производителей. Результат — массив `goods`, в карточках используются `brand`, `number`, `name`.

### Получение предложений и аналогов

Параметры: `key`, `number`, `brand`, `analogues=on`, `info=on`. По документации вложенные аналоги приходят, когда переданы `brand` и `analogues=on`.

Товар (`goods`) может включать `goodsID`, `brand`, `number`, `name`, `count`, `rate`, `warehouses`, `analogues`, `notRefund`.

Складское предложение (`warehouses`) может включать `code`, `id`, `own`, `shipmentDate`, `price`, `stock`, `notRefund`.

**Цена для отображения — только `warehouses[].price`**. Поле `goods[].price` не использовать: в документации оно отмечено как оставленное для совместимости.

Обрабатывать ошибку в поле `error`, ответ с одной пустой структурой при отсутствии товара и товары с нулевым остатком. Параметры запроса должны быть корректно URL-кодированы.

### Ключ и браузерные ограничения

- Ключ вводится локально в `.env.local` и не коммитится в Git.
- Переменные `VITE_*` **не являются секретными**: значение окажется в браузерном коде/запросах. Это осознанное ограничение локального тестового проекта; используйте только ключ, допустимый для клиентского применения.
- Полученный при открытии URL ответ `{"error":"Empty key!"}` подтверждает доступность сервера, **но не подтверждает CORS**. Кросс-доменные запросы нужно проверить из работающего Vite-приложения.
- Приложение и запросы должны оставаться в рамках локальной тестовой среды; не обходить ограничения браузера отключением его защиты.

## 5. Визуальные требования

Из референса `docs/reference.jpg` берём только **цветовую гамму** и **общий современный автомобильный стиль**: светлые поверхности, красные акценты, графитовую типографику и скруглённые элементы. Hero-блок на этапе 4 использует собственное согласованное изображение **Ford Mustang** из `public/images/hero-mustang.png` с затемнением. Всё остальное следует согласованной функциональной структуре; не копировать каталог, корзину, аккаунт, блоки магазина или чужую навигацию.

- Светлый фон: белый / светло-серый.
- Красные акценты и кнопки; графитовый текст.
- Минималистичные карточки с тонкими границами/легкими тенями.
- Адаптивная вёрстка, читаемый текст на фото, удобные таблицы на мобильных экранах.
- Логотип можно разработать позднее; до этого допустима текстовая версия YURAL FAVORIT.
- Для Hero выбрано предоставленное изображение Ford Mustang: `public/images/hero-mustang.png`. Использовать его с подходящими правами использования; не подменять произвольным автомобилем. Подключение изображения к странице — этап 4.

## 6. Не входит в MVP

Авторизация, регистрация, личный кабинет, корзина, заказы, оплаты, каталог категорий, история поиска, сортировка, фильтрация, база данных, собственный backend, публичный деплой.

## 7. Приёмка MVP

1. Работают все страницы и фиксированный адаптивный Header.
2. Поиск по артикулу отображает реальные карточки с четырьмя оговорёнными элементами.
3. Страница выбранной детали отображает отдельно предложения производителя и аналоги, с ценами из конкретных складов.
4. Отрабатывают пустой ввод, загрузка, отсутствие результатов и ошибки API.
5. Кнопка возврата сохраняет текущий поиск и не выполняет ненужный повторный запрос.
6. Прямой URL страницы деталей поддерживается.
7. Вёрстка адаптивна; приложение успешно собирается.
8. Отсутствует непредусмотренный функционал; секреты не попали в Git.
