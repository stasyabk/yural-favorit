# YURAL FAVORIT — требования к MVP

**Версия:** 1.0  
**Статус:** согласованные требования к локальному тестовому проекту

## 1. Назначение

YURAL FAVORIT — тестовый веб-сайт для поиска автомобильных запчастей по артикулу. Данные о товарах, производителях, складских предложениях и аналогах приходят из действующего API Favorit Parts («Проценка»). Публичное размещение, продажи и личные кабинеты на этом этапе не планируются.

## 2. Стек и ограничения

- React на JavaScript (без TypeScript), сборка Vite.
- Redux Toolkit и RTK Query для запросов, кеша и состояний серверных данных.
- React Router для навигации.
- Bootstrap 5 и собственный CSS для оформления.
- `fetchBaseQuery` для HTTP-запросов; Axios и `createAsyncThunk` для стандартных API-запросов не нужны.
- **Без отдельного backend и proxy**: тестируем прямые запросы из браузера. Если политика CORS или другая браузерная блокировка мешает, останавливаем интеграцию и согласовываем решение, а не добавляем proxy самовольно.

## 3. Общий интерфейс

### Закреплённый Header (sticky)

На всех страницах: слева логотип/надпись **YURAL FAVORIT**, справа разделы **Главная**, **О нас**, **Контакты**. На узких экранах — адаптивная навигация. Header использует position: sticky с top: 0, остаётся в потоке документа и не перекрывает начальный контент; компенсационные отступы не нужны. Клик по «Главная» или логотипу всегда открывает / сверху (scrollY = 0), в том числе уже находясь на /. Поиск, выдача и кеш не сбрасываются; возврат «Назад» из детали по-прежнему позиционирует главную у результатов. Фон Header — #F3F3F3, нижняя линия — 2px #E92327. Обычные ссылки — #252525; hover и активная ссылка — #E92327 с красным подчёркиванием. Цвет и появление линии меняются за 0.2s; активное подчёркивание постоянно.

### Главная (`/`)

- Крупная фоновая фотография **Ford Mustang** с затемнением в первом экране.
- По центру первого экрана — заголовок «Поиск автозапчастей», краткий подзаголовок, строка артикула и кнопка «Найти».
- После поиска **ниже поискового блока** показывается вертикальный список найденных деталей/производителей.
- Каждая строка содержит **только**: производитель, артикул, наименование, кнопку **«Посмотреть цены»**. Цена, остаток и склады в строке результата не отображаются.
- На Desktop и Tablet (от 768 px) результаты расположены горизонтально в четырёх колонках: производитель, артикул, наименование, «Посмотреть цены», с общей строкой заголовков. На Phone (менее 768 px) производитель и артикул расположены сверху, наименование ниже, кнопка внизу на всю ширину. Длинный текст переносится; горизонтальной прокрутки нет. На ширине 768–991px подпись кнопки «Посмотреть цены» не переносится; допускаются уменьшенные боковые отступы кнопки и ячеек.
- Центральный блок Hero поднят примерно на 70 px относительно вертикального центра, с безопасными отступами на коротких экранах.
- Поиск запускается кнопкой и клавишей Enter; пустой ввод не отправляется.
- Состояния: до поиска, загрузка, успех, ничего не найдено, ошибка.
- При отсутствии реальных товаров показывается только сообщение «По вашему запросу ничего не найдено»; список, его заголовки и счётчик скрыты. Пустая структура, технический goodsID или артикул без производителя не считаются найденным товаром.
- После завершения поиска (в том числе пустого) выполняется плавная прокрутка: нижняя граница sticky Header находится на 10px ниже нижней границы Hero. Заголовок результатов либо пустое сообщение полностью видны. При возврате на главную с сохранённым поиском эта же позиция устанавливается сразу, без новой плавной автопрокрутки.
- Поисковая строка остаётся доступной для последующего поиска; история нескольких запросов не отображается и не хранится как отдельная функция.

### Цены и аналоги (`/parts/:brand/:number`)

- Над таблицами показываются выбранный производитель и артикул.
- Первая таблица: **предложения деталей выбранного производителя**.
- Ниже вторая таблица: **уникальные аналоги по паре производитель + артикул**.
- Столбцы первой таблицы: производитель, артикул, наименование, цена, остаток, склад, дата отгрузки.
- Столбцы списка аналогов: производитель, артикул, наименование, кнопка «Посмотреть наличие». Цены, остатки и склады аналогов в списке не выводятся. Кнопка ведёт на /parts/:brand/:number выбранного аналога; его предложения и аналоги загружаются через RTK Query.
- Аналоги без складских предложений также присутствуют в списке. Дубли объединяются по точным значениям производителя и артикула, порядок первого появления сохраняется. Если первое наименование пустое, используется первое последующее непустое.
- Цены отображаются числом без обозначения валюты (согласовано для этапа 5); отдельная поясняющая надпись о валюте не показывается. Отсутствующие значения — «—»; нулевые цена и остаток показываются как 0. Дата отгрузки сохраняет время и часовой пояс исходного API.
- **В первой таблице одна строка = предложение одной детали на одном складе**. Одна деталь может повторяться в нескольких строках.
- Складская таблица не имеет ограничения высоты или внутренней вертикальной прокрутки: все предложения показаны сразу. На узких экранах сохраняется горизонтальная прокрутка в собственном контейнере.
- Сортировки и фильтров нет.
- При отсутствии аналогов или складских предложений показывается понятное пустое состояние, а не выдуманные строки.
- Есть кнопка **«Назад»**: через историю React Router. Деталь → Главная с сохранённым поиском возвращает позицию как после поиска; Аналог → предыдущая деталь открывает её с scrollY = 0. Прямой URL без внутренней истории → главная сверху. Восстановлением прокрутки управляет только приложение, автоматическое восстановление браузера отключено.
- При возвращении в рамках текущей сессии приложения сохраняются введённый артикул и результаты поиска; повторный запрос при обычном возврате не должен выполняться. Параметры поиска хранятся в searchSlice, последний активный результат удерживается подпиской RTK Query на уровне общего App. Изменение ввода без отправки не меняет показанный артикул; новый поиск заменяет предыдущую выдачу. Полная перезагрузка приложения начинает новую сессию, постоянное хранение не требуется.
- URL страницы детали должен работать при прямом открытии; параметры `brand` и `number` кодируются надлежащим образом.

### Информационные страницы

- `/about` — «О нас», временное содержимое.
- `/contacts` — «Контакты», временное содержимое.

## 4. API

Источник: предоставленный пользователем PDF `wsprice.pdf` — документация Web-сервиса «Проценка» от 06.03.2023.

**Метод и URL:** `GET http://api.favorit-parts.ru/hs/hsprice/`.

### Поиск по артикулу

Параметры: `key` (клиентский ключ), `number` (артикул); без `brand` API возвращает товары разных производителей. Результат — массив `goods`, в строках используются `brand`, `number`, `name`.

### Получение предложений и аналогов

Параметры: `key`, `number`, `brand`, `analogues=on`, `info=on`. По документации вложенные аналоги приходят, когда переданы `brand` и `analogues=on`.

Товар (`goods`) может включать `goodsID`, `brand`, `number`, `name`, `count`, `rate`, `warehouses`, `analogues`, `notRefund`.

Складское предложение (`warehouses`) может включать `code`, `id`, `own`, `shipmentDate`, `price`, `stock`, `notRefund`.

**Цена для отображения — только `warehouses[].price`**. Поле `goods[].price` не использовать: в документации оно отмечено как оставленное для совместимости.

Обрабатывать ошибку в поле `error`, ответ с одной пустой структурой при отсутствии товара и товары с нулевым остатком. Параметры запроса должны быть корректно URL-кодированы.

### Ключ и браузерные ограничения

- Ключ вводится локально в `.env.local` и не коммитится в Git.
- Переменные `VITE_*` **не являются секретными**: значение окажется в браузерном коде/запросах. Это осознанное ограничение локального тестового проекта; используйте только ключ, допустимый для клиентского применения.
- Полученный при открытии URL ответ `{"error":"Empty key!"}` подтверждает доступность сервера, **но не подтверждает CORS**. Кросс-доменные запросы нужно проверить из работающего Vite-приложения.
- Приложение и запросы должны оставаться в рамках локальной тестовой среды; не обходить ограничения браузера отключением его защиты.

## 5. Визуальные требования

Из референса `docs/reference.jpg` берём только **цветовую гамму** и **общий современный автомобильный стиль**: светлые поверхности, красные акценты, графитовую типографику и скруглённые элементы. Hero-блок на этапе 4 использует собственное согласованное изображение **Ford Mustang** из `public/images/hero-mustang.png` с затемнением. Всё остальное следует согласованной функциональной структуре; не копировать каталог, корзину, аккаунт, блоки магазина или чужую навигацию.

- Светлый фон: белый / светло-серый.
- Красные акценты и кнопки; графитовый текст.
- Минималистичные строки результатов с тонкими разделителями.
- Адаптивная вёрстка, читаемый текст на фото, удобные таблицы на мобильных экранах.
- Логотип можно разработать позднее; до этого допустима текстовая версия YURAL FAVORIT.
- Для Hero выбрано предоставленное изображение Ford Mustang: `public/images/hero-mustang.png`. Использовать его с подходящими правами использования; не подменять произвольным автомобилем. Vite использует стандартную корневую папку public; публичный URL — /images/hero-mustang.png, файл production-сборки — dist/images/hero-mustang.png.

## 6. Не входит в MVP

Авторизация, регистрация, личный кабинет, корзина, заказы, оплаты, каталог категорий, история поиска, сортировка, фильтрация, база данных, собственный backend, публичный деплой.

## 7. Приёмка MVP

1. Работают все страницы и закреплённый адаптивный Header (sticky).
2. Поиск по артикулу отображает реальные строки с четырьмя оговорёнными элементами.
3. Страница выбранной детали отображает отдельно предложения производителя и аналоги, с ценами из конкретных складов.
4. Отрабатывают пустой ввод, загрузка, отсутствие результатов и ошибки API.
5. Кнопка возврата сохраняет текущий поиск и не выполняет ненужный повторный запрос.
6. Прямой URL страницы деталей поддерживается.
7. Вёрстка адаптивна; приложение успешно собирается.
8. Отсутствует непредусмотренный функционал; секреты не попали в Git.

Кнопка «Назад»: фон #F3F3F3, текст #252525, стрелка влево, padding 12px 20px, min-height 44px, border-radius 999px. При hover фон #E6E6E6 и лёгкое затемнение границы, переходы 0.2s. Оформление не меняет логику Router-навигации.
