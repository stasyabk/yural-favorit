# YURAL FAVORIT

Тестовое frontend-приложение для поиска автомобильных запчастей по артикулу и просмотра предложений Favorit Parts API. Проект демонстрирует работу с внешним API, кешированием серверных данных, маршрутизацией и адаптивным интерфейсом.

Приложение предназначено для локального запуска. Данные о товарах, ценах, остатках и аналогах поступают из реального API; отдельный backend и proxy не используются.

## Технологии

- React 19 и JavaScript.
- Vite 8.
- Redux Toolkit и React Redux — клиентское состояние поиска.
- RTK Query и `fetchBaseQuery` — запросы, кеш, загрузка и ошибки.
- React Router 7 — `createBrowserRouter`, `RouterProvider`, вложенные маршруты через `Outlet`.
- Bootstrap 5 и собственный CSS.
- ESLint и встроенный тестовый раннер Node.js (`node:test`).

## Возможности

- Поиск по артикулу кнопкой или клавишей Enter.
- Выдача с производителем, артикулом, наименованием и переходом к ценам.
- Таблица складских предложений выбранной детали: цена, остаток, склад и дата отгрузки.
- Список уникальных аналогов по производителю и артикулу с переходом к их предложениям.
- Сохранение ввода и результатов при переходах между поиском, деталью и аналогами в текущей сессии без повторного поискового запроса при обычном возврате.
- Сброс поиска кнопкой × с отменой выполняющегося запроса и возвратом фокуса в поле; общий кеш RTK Query не очищается.
- Обработка пустого ввода, загрузки, отсутствия товаров, складских предложений и аналогов, ошибок API и сети.
- Адаптивная вёрстка, закреплённый Header и мобильное меню. Складская таблица на узких экранах прокручивается горизонтально внутри своего контейнера.

Поиск не сохраняется после полной перезагрузки страницы. Разделы «О нас» и «Контакты» содержат временные тексты. Корзина, регистрация, оформление заказов, сортировка и фильтры не входят в MVP.

## Установка

Требуются Node.js **22.12 или новее** и npm. Из корневой папки проекта установите зависимости по `package-lock.json`:

```bash
npm ci
```

## Настройка окружения

Создайте в корне проекта файл `.env.local` на основе `.env.example`:

```dotenv
VITE_FAVORIT_API_URL=http://api.favorit-parts.ru/hs/hsprice/
VITE_FAVORIT_API_KEY=
```

Укажите в `VITE_FAVORIT_API_KEY` собственный действующий ключ, разрешённый для тестового клиентского использования. Без ключа запросы не отправляются, приложение показывает сообщение об ошибке. `VITE_FAVORIT_API_URL` задаёт адрес API; при отсутствии значения используется адрес из примера.

`.env.local` исключён из Git. Переменные `VITE_*` доступны в браузере и встраиваются в клиентскую сборку: такой способ не обеспечивает секретность ключа. Не используйте приватные серверные ключи и не публикуйте реальные значения в репозитории.

После изменения переменных окружения перезапустите dev-сервер; для готовой сборки потребуется повторная сборка.

## Запуск

```bash
npm run dev
```

Откройте адрес, указанный Vite в терминале; обычно это `http://localhost:5173/`.

Для проверки поиска можно использовать артикул `0986424794`, который применялся при интеграционной проверке. Актуальные товары, цены и остатки зависят от ответа API и прав используемого ключа.

### Сборка и локальный просмотр

```bash
npm run build
npm run preview
```

Сборка создаётся в `dist/`. Команда `preview` служит для локального просмотра сборки; адрес отображается в терминале.

### Проверки

```bash
npm test
npm run lint
```

Тесты проверяют нормализацию ответов, ошибки сервисного слоя, форматирование цен и остатков, обработку пустых данных, уникальность аналогов и клиентское состояние поиска. В изолированных тестах используются тестовые ответы и ключи, реальные учётные данные не требуются.

## Маршруты

| Путь | Страница |
| --- | --- |
| `/` | Главная и поиск |
| `/parts/:brand/:number` | Цены, складские предложения и аналоги |
| `/about` | О нас |
| `/contacts` | Контакты |

Кнопка «Назад» использует историю React Router, а при прямом открытии детали без внутренней истории возвращает на главную. Возврат к поиску восстанавливает позицию результатов; переход на главную через Header или логотип открывает её сверху, сохраняя поиск.

## Работа с API

Серверные данные хранятся в RTK Query, а `searchSlice` содержит только введённый и подтверждённый артикулы. Нормализация ответов и форматирование вынесены из UI в сервисный слой и утилиты.

Цены берутся из `warehouses[].price`, остатки — из `warehouses[].stock`, дата отгрузки — из `warehouses[].shipmentDate`. Цена отображается числом без обозначения валюты; дата — исходной строкой API с временем и часовым поясом. Ответ HTTP 200 с полем `error` обрабатывается как ошибка.

API использует HTTP. Запросы с HTTPS-страницы могут блокироваться браузером как mixed content; доступ из приложения также зависит от CORS API. При браузерной блокировке не отключайте защиту браузера: проект не содержит обходов, backend или proxy. Публичный деплой не входит в рамки задания.
